# `tools/theme-pkg-check.mjs` 使用说明

一个主题包（`*.themepkg.json`）**能不能导入 App**，以及导入后**最差那一格配色是多少**，
在命令行上就能定死，不需要浏览器、不需要打包 APK、不需要装依赖。

```bash
# 必须在项目根跑（工具用相对路径 import 了 weather-app/js/lib/ 里的判据）
node tools/theme-pkg-check.mjs 你的主题.themepkg.json
```

写主题本身的规矩、令牌清单、`glass` / `lace` 怎么取值，在
**[主题插件开发范式.md](../主题插件开发范式.md)**；这份文档只讲**这条命令怎么用、输出怎么读、
它不管什么**。

---

## 1. 四种跑法，按你需要挑

| 命令 | 什么时候用 | 会改文件吗 |
|---|---|---|
| `node tools/theme-pkg-check.mjs 包.json` | 每次改完配色就跑一次，拿退出码 | 不会 |
| `… 包.json --explain` | 读数不达预期，想知道「最差那一格的底到底是怎么叠出来的」 | 不会 |
| `… 包.json --fix` | 已经确定不过线，想要一个「在允许范围内怎么改才过线」的候选值 | 不会（只打印） |
| `… 包.json --all` | 一次把 `--explain` 和 `--fix` 都打出来 | 不会 |

**工具全程只读。** `--fix` 打印的是候选值，落盘由你做 —— 与 `tools/theme-glass-scan.mjs`
（全文没有 `writeFileSync`）、`tools/shell-check.mjs`（只查不改）同一条纪律。理由：过线不等于好看，
把「算术上最小改动」的那组数直接写回你的主题，是最容易毁掉一套配色的做法。

## 2. 输出逐行怎么读

拿 `主题插件开发范式.md` §0 那份最小例子跑（可以直接复制它存成文件）：

```
✓ 形状合格 · 素材 0KB · 18 令牌 · CSS 0.0KB
  最低比 5.454 @ muted@弹窗/storm@#6d7a8d · 达标线 5.0 · ✓ 过线
```

- **第一行是「形状」**：走的是 App 里那份 `themePlugin.validate`（`weather-app/js/lib/themePlugin.js`）
  —— 格式号、id 规则、§1 那三道硬闸（不执行代码 / 锁作用域 / 不引外部资源）、体积预算、远程资源，
  全部同一条码路。所以这行的 ✓
  和导入时弹的「已启用」是同一件事，不存在第二套尺子。
- **`最低比` 是「算术」**：走 `themeScan.worstContrast`（`weather-app/js/lib/themeScan.js`），
  内置主题的离线扫描 `tools/theme-glass-scan.mjs` import 的也是它。
- **`@ muted@弹窗/storm@#6d7a8d`** 是「哪个字色 压 哪块底」，`角色@底名`。底名的四种形状见 §4。
- **达标线 5.0** = WCAG AA 的 4.5 + 0.5 余量。余量是故意的：真机卡面底下是**模糊过的复合**，
  量到的不是这两个纯色标，压线过关不算过关。

加 `--explain` 会把最差那一格拆成叠色链：

```
最差那一格：muted 压「弹窗/storm@#6d7a8d」= 5.454（达标线 5.0）
  字色  muted = #545e6d（--muted-base #5c6675 掺 --ink 12% 之后的实测值）
  底  #e9eaec ← 页面底 = storm 渐变的端点 #6d7a8d ← --veil rgba(20,28,40,.45) 压住它 ← 卡面 α=0.88 的 --card #ffffff 压住那层
  比值 5.454
  同一块底上四个角色（看是字色的问题还是底的问题）：
    ink    #1b2330 压这块底 = 13.120
    muted  #545e6d 压这块底 = 5.454
    pop    #2c5a86 压这块底 = 5.987
    accent #33507a 压这块底 = 6.790
```

最后那四行是**最有判断力的一段**：同一块底上四个角色并排念，一眼看出是「这块底本身不行」
（四个都低）还是「某个字色不行」（只有 muted 拖）。注意 `muted` 显示的是**掺完之后**的实测值，
不是你 JSON 里写的 `--muted-base`。

## 3. 退出码

| 码 | 含义 | 怎么办 |
|---|---|---|
| `0` | 过线，可导入 | 继续做观感核对（§8） |
| `1..80` | 差几条错误就是几条（`validate().errors.length`） | 逐条改，见 范式.md §8 的对照表 |
| `81` | 读不到文件（含不带参数跑的用法提示） | 检查路径；**必须在项目根跑** |
| `82` | JSON 解析失败 | 编辑器里查逗号/引号；`jsonc` 注释是不被允许的 |
| `83` | 判据抛错 | 通常是某个令牌不是十六进制。这条码也用于 `--explain` 拆解与判据对不上 |
| `84` | 量出来 **0 条底** | **这不是合格**，是判据什么都没看到。见 §4 |
| `85` | `--fix` 在允许范围内无解 | 别再迭代参数了，要动的是设计（§6） |
| `86` | 不认识的模式开关 | 只有 `--explain` / `--fix` / `--all` |

`90+` 归 `tools/run-checks.mjs`，`93~98` 归 `tools/falsify.mjs`，这套 `81..86` 不复用它们。

**`--fix` 找到候选也不会把码改成 0。** 包本身还是装不进去 —— 正确的闭环是
「把候选填回 JSON → 重跑 → 拿到 0」，而不是「看到候选就当过了」。

## 4. 四类底，和「判据没量到的地方」

判据把「这套主题的字真会遇到的每一块底」铺成四族，底名的形状就是族名：

| 族 | 底名长这样 | 吃 `glass.a` 吗 |
|---|---|---|
| ① 卡面悬在页面渐变上 | `bg`、`storm@#6d7a8d` | 吃（α 越小透出越多底） |
| ② 卡面里的子面板 | `面板/code-bg`、`面板/field-bg` | **完全不吃** |
| ③ 弹窗 | `弹窗/rain@#…` | 吃 |
| ④ 装饰（`lace`） | 以上任一种 `+装饰` | 画在卡面之上的满额 `lace` 叠一次；画在卡面之下的只漏上 `(1−α)·lace`；弹窗那一支不叠满额，只算漏上来的 |

②那一族不吃 α 是**项目里最容易搞错的一件事**：`--hint-bg/--code-bg/--field-bg/--ok-bg/--err-bg`
自己半透在卡面上，但复合公式里没有卡面透明度这一项。所以「过不了线就抬 α」对它是废话。
工具会把这类话说在前面：

```
  ⚠ 抬 glass.a 对它无效 —— 「面板/」那一族底不吃 α
  ⚠ 调 glass.mix 对它无效 —— CSS 里只有 --muted 吃 mix，现在最差的是 pop
  ⚠ 降 lace 对它无效 —— 这一格底下没压装饰层
```

### 【判据没量到的地方】—— 优先级最高的一段，因为它零误报

判据对「拿不到的令牌」是 `try/catch` 跳过的（`themeScan.js` 里那几支），而 `validate` 并**不强制**
`--veil` 和全部五块子面板。于是可能出现这种包：**读数是绿的，但那一族底根本没进验收。**

把示例里的 `--veil` 删掉再跑，就是这个效果：

```
✓ 形状合格 · 素材 0KB · 17 令牌 · CSS 0.0KB
  最低比 5.638 @ muted@面板/code-bg · 达标线 5.0 · ✓ 过线

【判据没量到的地方】这几条不是错误，但会让上面那个读数偏乐观：
  ! 「弹窗」那一族底整支没量到（多半是包里没给 --veil，themeScan 就把这一支 catch 掉跳过了）。
    历史上漏的正是这一支：2026-10-04 离线说每套 ≥5.0，真机正文只剩 4.53。补一个 --veil 再重量。
```

注意读数是**5.638，比带着 `--veil` 的 5.454 更好看** —— 因为它少算了一族最坏的底。
这种「越缺越绿」是本工具最想把话说清的一件事，所以它排在所有提醒之前。
报的是 `r.bgs` 里**实际缺了哪一族**，不是去猜令牌给没给，因此永远不会和判据走样。

`84`（0 条底）是同一件事的极端情况：一族都没铺出来。正常包里到不了 —— 只要 `--bg` 在就至少有一条底，
所以把它当护栏看，别当常见码（它存在的意义是「量不到东西时绝不报绿」）。

## 5. 【css 里判据量不到的大面积规则】

对比度判据只看**令牌**，看不到你 `css` 字段里糊上去的整屏层。工具补了一层静态扫描：
规则**主体**（最后一个复合选择器）落在 `body` 或 `.app` 上，且色值不透明度 ≥0.3 或 `opacity` >0.6，
就点出来：

```
【css 里判据量不到的大面积规则】以下 1 处**没被量过**，不是说它们有问题；
要确认只能走真机截图（警告不计入退出码）：
  ~ body[data-theme="demo"]::before —— background 色值不透明度最高 0.62
```

三个刻意的取舍：

- **只报主体**。`body[data-theme="x"] .current-card::after` 这种只有几十 px 的层不报，
  否则一条以 `body[...]` 开头的长选择器清单会把信号稀释光。
- **措辞是「没被量过」，不是「有问题」**。这一层要确认只能走真机。
- **不计入退出码**。也不写进 `validate().warns`：设置页里那条提示语取的是
  `warns[0]`，塞进去会让用户看到警告而不是「装好了」。

超过 6 处会截断（`CSS_WARN_MAX`，见 §7）。

## 6. `--fix` 的边界

它只在这几条轴上搜索：`glass.a`、`glass.mix`、`lace`，以及三个可挪的字色令牌
（`--muted-base` / `--pop` / `--accent`）。**`--ink` 绝不动** —— 那是整套主题的脸。

**不假设任何单调性。** 做法是把 `(a, mix, lace)` 铺成网格，按**改动代价**排序，
best-first 逐个喂给同一个 `worstContrast`，第一个过线的就是代价最小的解。
为什么不用二分/爬山：§4 那三行「无效轴」就是单调性会破产的地方 ——
「α 越大越安全」对 ② 族不成立，「mix 越高越安全」对 `pop`/`accent` 不成立。
第一版 `theme-glass-scan.mjs` 就为同一个形状的坑记过账（把 mix 一路加到封顶去救 `pop`）。

零代价档全灭，才在几个锚点上试挪字色，且有三条判停：
最差格落在 `ink` / 单个令牌挪够 12 步（24%，再深就不叫微调）/ 总步数超 `COST_CAP`。
三条都不满足就是 `85 无解`。把示例的 `--accent` 换成 `#f0e6c8`（浅米色压在白卡上）跑 `--fix`，
得到的就是这个 —— 注意它同时把两条无效轴说在前面：

```
  ⚠ 调 glass.mix 对它无效 —— CSS 里只有 --muted 吃 mix，现在最差的是 accent
  ⚠ 降 lace 对它无效 —— 这一格底下没压装饰层

✗ 在允许范围内无解：扫了 533 档（网格 533 档），挪字色也救不回来。
  要么改深字色本身（超出本工具的预算）、要么换掉那块底、要么这主题就不该过 ——
  三个都是设计决定，不是工具能替你定的。
```

一个真实的候选输出（把 `--muted-base` 改成 `#8b96a6` 之后）：

```
  候选：glass.a 88→88（不动） · glass.mix 12→40 · lace 0→0（不动） · blur 不搜，由 a 派生 = 11
  字色：--muted-base #8b96a6→#828d9d（3 步）
  最低比 5.060 @ muted@弹窗/storm@#6d7a8d  ✓过线（达标线 5.0）
  代价：α 抬 0 档 · mix 变 28 · lace 变 0 · 字色挪 3 步　（搜了 533 档）
  ⚠ 这个候选把 glass.mix 顶到了上限 40。mix 再高 --muted 就和 --ink 同色了
    （应用允许到 62 才拒，但层次也是设计，不是免费的）—— 与其照抄，不如改深 --muted-base 本身或换掉那块底。
  ⚠ 这只证明算术过线。落盘后仍要按 主题插件开发范式.md §9 走真机截图看观感。
```

最后那两条 ⚠ 不是免责声明，是结论的一部分：**顶到 `mix` 上限的候选不算建议成功**。
它证明的是「存在一组数能过线」，不是「这套配色应该长这样」。
（顺带：`blur` 不参与搜索，它由 α 派生 —— 见 范式.md §4 的耦合关系。）

## 7. 旋钮走环境变量，不走 argv

照 `tools/theme-glass-scan.mjs` 的写法，阈值不占命令行位置：

```bash
MIX_LIMIT=30 COST_CAP=6 node tools/theme-pkg-check.mjs 包.json --fix
```

| 变量 | 默认 | 作用 |
|---|---|---|
| `MIX_LIMIT` | 40 | 工具**建议**的提档上限（应用允许到 62 才拒）；也是搜索网格的右边界 |
| `A_FLOOR` | 55 | `glass.a` 搜索下限，与 `validate` 一致 |
| `COST_CAP` | 8 | 挪字色的总步数预算 |
| `CSS_WARN_MAX` | 6 | css 盲区那一段最多列几条 |
| `SCAN_CAP` | 20000 | `--fix` 最多试多少档；触顶就停止搜网格、转入挪字色，最终仍可能报 `85` |

`MIX_LIMIT` 和 `A_FLOOR` 同时决定搜索空间：把 `MIX_LIMIT` 调到 62 会放宽候选（顶格那条 ⚠ 也跟着挪）。
另有一条 ⓘ 是给**包自己声明的值**的：`glass.mix` 超过 `MIX_LIMIT` 但还在应用允许的 62 以内时，
它说「能装，但 `--muted` 已经开始和 `--ink` 同色」—— 这是全工具唯一一处「应用允许、工具不建议」的取值。

## 8. 它不管什么（别把绿处理解成「这主题好了」）

绿的含义**只有**：能被 App 接受导入，且四个验收字色在四族算得出的底上最差 ≥5.0。以下都要人看：

1. **观感**。配色是否舒服、装饰是否与内容打架、立绘是否被 UI 挡住 —— 算术判不了。
2. **裁切与取景**。2026-10 那次真实缺陷：竖屏下人物主体被裁在取景窗边缘，横屏又整张偏走。
   每个 `background-position` 都合法，判据全绿，**只有截图能看出来**。
3. **动画与滚动性能**。42 层 `backdrop-filter` 压在位图底上会不会掉帧，工具不看。
4. **@media 分支里的实际渲染**。判据量的是令牌值，不是浏览器算完 `color-mix()` 的落点。
5. **不在验收令牌上的字**。比如 `css` 里手写死的一个 `color: #ccc` —— 那走的是第 5 节的警告，
   不是对比度闸。

第 1~3 条**没有可信的机器通道**：Qoder 的应用内浏览器面板是 0×0 隐藏页、
`visibilityState=hidden`、CSS 动画整体冻结，在里面量出来的数值和画面都不作数。
能信的真机截图只有一条路：

```bash
adb exec-out screencap -p > 核对.png     # 横屏、竖屏各一张；再翻到最暗那个天气态（一般是 storm）
```

## 9. 配套测试与相邻工具

- `node tests/theme-pkg.test.mjs` —— 全绿 7 条。钉住本工具依赖的六道闸：基准包可导入、
  保留令牌、CSS 作用域、未声明素材（没有 `assets` 字段时也要查）、AA、
  **缺 `--veil` 会让「弹窗」那一族消失**、`lace>0` 时会生成「+装饰」那一族。
  退出码 = 红条数。输出形状是按 `tools/falsify.mjs` 的契约写死的（大写 `PASS` 行首、
  `FAIL 名字 ⟵ 明细`），别照抄 `glass.test.mjs` 的小写 `pass` 和 `got=`。
- `node tools/theme-glass-scan.mjs` —— 同一把尺子量**内置**那几套主题（输入是刮 `styles.css`）。
- `node tools/theme-agent-loop.mjs 包.json` —— 本工具管不到的那一半：把包真装进页面、听 App 自己怎么说、
  切上去、出一张图。手册在 [theme-agent-loop.md](theme-agent-loop.md)。它第一步就是调本工具，
  离线闸不过就不碰页面，所以「先跑我、再跑它」是正常顺序。
- `node tools/shell-check.mjs` / `tools/anchor-audit.mjs` —— 与本工具无关的服务清单与变异锚点。

## 10. 一条噪音先说清

跑这条命令时 stderr 会先来一行 `MODULE_TYPELESS_PACKAGE_JSON`，那是 Node 的 loader 在抱怨
`weather-app/js/*.js` 没声明模块类型，**不是这个工具说的话**，也不计入退出码。
别为它给根 `package.json` 加 `"type": "module"` —— 那会把全仓 `.js` 的解析规则一起改掉。
（依赖这条自动识别，所以 Node 要 22 以上；本仓实测 24.x。）
